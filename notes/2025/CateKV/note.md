## 一句话总结

CateKV 通过发现注意力头的**序列一致性**（sequential consistency）现象，将注意力头分为"一致性头"和"自适应头"，利用变异系数（Coefficient of Variation）算法精确分类，在一致性头中仅保留关键 KV 对、自适应头中保留大部分 KV 对，从而在保持接近全注意力精度的前提下，将内存使用降低 2.72×、解码延迟降低 2.18×、批处理吞吐量提升 3.96×。

## 摘要翻译

大型语言模型（LLM）在处理长上下文任务方面展现了强大的能力，但由于巨大的内存需求和推理延迟，处理长上下文仍具挑战性。在本工作中，我们发现某些注意力头的注意力模式展现出**序列一致性**，可以通过基于变异系数的算法持续识别。受此观察启发，我们提出了 **CateKV**，一种混合 KV 缓存方法，仅在一致性头中保留关键的 token 信息以减少 KV 缓存大小和计算开销，同时在自适应头中保留大部分 KV 对以确保高精度。我们在长上下文基准测试上进行了全面评估，结果表明：在保持与全注意力相当的精度的同时，CateKV 在单样本输入中将内存使用降低 2.72×、解码加速 2.18×，在批处理场景中将吞吐量提升 3.96×。

## 研究动机

1. **长上下文推理的挑战**：随着 LLM 支持 128K 甚至 1M 的上下文窗口，自回归推理需要存储和检索所有 KV 缓存，导致计算成本、内存消耗和运行时间大幅增加。例如，Llama-3-8B-Instruct-262k 模型从 1K 扩展到 1M 时，推理延迟增加超过 3000 倍。

2. **现有方法的局限性**：
   - **KV 缓存驱逐策略**（如 StreamingLLM、H2O、SnapKV、PyramidKV）：通过丢弃 KV 对减少缓存大小，但通常导致显著的精度损失，因为移除了对任务性能至关重要的信息。
   - **KV 缓存检索策略**（如 Quest、ShadowKV）：通过保留完整 KV 缓存并在解码时选择性检索来维持精度，但无法缓解高内存使用问题，限制了批处理大小和吞吐量。
   - **头部分类方法**（如 MInference、RazorAttention、DuoAttention）：虽然认识到不同注意力头的异质性，但未充分利用预填充和解码阶段之间的交互。

3. **核心洞察**：作者发现某些注意力头在预填充和解码阶段展现出**序列一致性**（注意力模式跨阶段稳定），而另一些头展现出动态激活（注意力分布随解码步骤显著变化）。如果能在预填充阶段捕捉这些模式，就可以利用序列一致性在解码阶段仅为一致性头维护关键 token 子集，从而同时减少 KV 缓存和加速注意力计算。

## 方法（技术细节）

### 3.1 注意力头的序列一致性

- **一致性头（Consistent Heads）**：表现出稳定的注意力模式，在所有解码步骤中聚焦于有限的 token 集合。
- **自适应头（Adaptive Heads）**：注意力分布随解码步骤显著变化，需要更大的注意力空间进行灵活的 token 交互。
- 这两种头存在于不同模型的多个层中（在 LongChat-7B、Llama-3、Phi-3、Yi 等模型中验证）。

### 3.2 头类型识别

#### 观测矩阵（Observation Matrix）
在预填充阶段，设置**观测窗口**（observation window）包含输入的最后几个 query token，用于识别头类型和关键 token：
$$A = \text{softmax}\left(\frac{Q[-L_{obs}:,:] K^T [L_{init}:-L_{rec},:]}{\sqrt{d}}\right)$$
其中 $L_{obs}$ 为观测窗口大小，$L_{init}$ 和 $L_{rec}$ 分别为初始 token 和近期 token 长度。

#### 变异系数得分（CV Score）
1. **二值化**：使用基于百分位的阈值 $k$ 和缩放因子 $\alpha$ 将观测矩阵二值化：
$$B = I(A \geq \Phi(k, \alpha))$$
2. **频率向量**：计算每个 token 被识别为关键的频率：
$$C = \sum_{i=0}^{L_{obs}} B_{i,:}$$
3. **CV 得分**：衡量注意力的集中性和相似性：
$$\text{score} = \frac{\sqrt{\frac{1}{n-L_{rec}-L_{init}} \sum_i (C_i - \mu(C))^2}}{\mu(C)}$$

#### 基于参考数据集的静态识别
- 利用参考数据集计算每个头被识别为一致性头的频率，基于自适应头比例 $r$ 确定最终的头类型。
- 高度的一致性：不同样本的分类结果重叠率超过 80%。
- 头类型识别结果在不同样本间高度一致，因此可以确定固定的头类型。

### 3.3 算法流程（Algorithm 1）

**预填充阶段：**
1. 计算 token 重要性（通过观测窗口内的注意力权重）
2. 将重要性向量划分为 chunk，取每个 chunk 的最大值
3. 根据头类型选择 KV 对：
   - **一致性头**：保留 top-k 个 chunk（仅保留少量关键 KV 对）
   - **自适应头**：保留 top-k 个 chunk（保留大部分 KV 对，比例为 $\eta$）

**解码阶段：**
- 一致性头：直接使用缓存的 KV 对
- 自适应头：从缓存中检索 KV 对（支持 all 或 query-aware）

### 3.4 理论分析

- 通过 Rademacher 复杂度界证明了 CV-based 方法的泛化能力。
- Token 保留精度的下界受三个因素影响：
  - $\lambda$：有效度量 token 相关性的概率
  - 预算控制：适当设置保留预算以最大化收益
  - $P_{head}$：CV-based 方法分类头类型的准确率

## 实验结果

### 实验设置
- **模型**：LLaMA-3-8B-Instruct-1048K、Phi-3-Mini-128K、Llama-3.1-8B、Yi-9B-200K、Qwen2.5-7B
- **基准**：RULER（128K）、LongBench（21 个任务）、Needle in a Haystack（20K-1M）
- **硬件**：单张 NVIDIA A100-80G GPU
- **基线方法**：StreamingLLM、SnapKV、PyramidKV、Quest、ShadowKV、DuoAttention

### 主要结果

#### 1. RULER 基准（128K）
- CateKV 在保留约 41% KV 缓存大小时，与全注意力相当甚至更好
- 在 Llama-3-8B-1M 上：平均精度 84.61%（全注意力 84.10%），提升 +0.51%
- 在复杂任务（多文档 QA、变量跟踪）上表现突出
- 优于所有基线方法

#### 2. LongBench 基准
- 5 个模型上平均精度下降不超过 0.3%
- CateKV 可将 KV 缓存降至 42%，同时保持与全注意力相当的性能
- 与 Quest、ShadowKV 集成后，内存使用进一步降低，精度损失不超过 0.2%

#### 3. Needle in a Haystack（20K-1M）
- 在 Llama-3-8B-1M 上，从 20K 到 1M token 上下文中表现出稳健的信息提取能力
- 内存和计算成本降低超过一半

#### 4. 与 DuoAttention 对比
- DuoAttention 在检索头比例低于 0.3 时精度显著下降
- CateKV 即使在自适应头比例降至 0.1 时仍能保持接近全注意力的性能
- CateKV 与 DuoAttention 互补，集成后显著提升 DuoAttention 在低全注意力头比例下的性能

#### 5. 与 MInference 集成
- CateKV 与预填充加速方法 MInference 结合不导致性能下降，甚至有轻微提升
- 预填充阶段的推理模式不影响头的序列一致性

#### 6. 效率评估

#### 7. 消融研究
- **自适应头比例 $r$**：性能在 $r$ 降至约 0.2 之前保持稳定，低于该阈值后显著下降；内存和延迟随 $r$ 降低近似线性下降。
- **保留比例 $\eta$**：$\eta$ 超过约 0.6 时，模型保持或超过全 KV 缓存性能；低于此阈值性能显著下降。
- **一致性头稀疏预算**：CateKV 对不同稀疏预算具有强鲁棒性，即使降至约 0.78%（1024）仍保持接近全注意力的性能。

1. **混合策略**：将注意力头分为一致性头和自适应头，针对性地选择保留策略，兼顾效率和精度。
2. **即插即用**：可与现有的加速方法（如 Quest、ShadowKV、DuoAttention、MInference）组合使用，进一步提升性能。
3. **高效识别**：基于变异系数的 CV 得分方法简单有效，分类结果在不同样本间高度一致，支持静态识别。
4. **显著加速**：内存降低 2.72×、解码加速 2.18×、批处理吞吐量提升 3.96×，同时精度损失极小。
5. **跨模型泛化**：在多个模型（Llama-3、Phi-3、Yi、Qwen2.5）和多个基准上验证了有效性。

7. **鲁棒性强**：一致性头对稀疏预算变化具有强鲁棒性，即使极小的缓存预算也能保持性能。

## 局限

1. **依赖参考数据集**：需要构建参考数据集来确定固定的头类型，且头类型识别的准确性依赖于参考数据集的质量。
2. **参数调优**：需要调整多个超参数（自适应头比例 $r$、保留比例 $\eta$、稀疏预算等），可能在不同任务和模型上需要不同的设置。
3. **GQA 处理**：对于 GQA 模型，观测矩阵需要计算组内头的平均值，这可能引入额外的近似误差。
4. **计算开销**：在预填充阶段需要计算 CV 得分和进行头分类，虽然可以静态化但增加了初始开销。
5. **与预填充加速的集成**：虽然可以与 MInference 等方法集成，但论文中未深入探讨集成后的最优策略。
6. **长上下文极端场景**：在超长上下文（如 1M tokens）场景下，虽然有 NIAH 验证，但缺乏对实际长文档任务的深入评估。
