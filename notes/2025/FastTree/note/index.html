FastTree: Optimizing Attention Kernel and Runtime for Tree-Structured LLM Inference

本 note 由 AI Agent 自动生成，基于论文原文提取。如有错误请以原文为准。

一句话总结

FastTree 是针对树结构 KV Cache 共享场景的 Attention kernel 和 runtime 优化系统，通过树结构自适应的贪心分组策略和高效 kernel 设计，实现对 FlashAttention/FlashInfer/DeFT 等的 2.1×–10.6× 加速，端到端吞吐提升达 2.2×。

摘要 (Abstract)

Tree-structured prefix sharing 在 LLM 应用中日益普遍，现有系统通过 radix tree 组织 KV cache 实现跨查询的缓存复用。但现有系统仍采用传统计算模式，导致冗余内存加载和 GPU tensor core 利用不足。FastTree 引入针对树结构 KV cache 的 GPU kernel，结合贪心启发式搜索最优的 context-queries 分组，并在运行时分割长上下文以缓解 GPU 利用不足问题。在 SGLang 上实现，端到端吞吐提升达 2.2×。

研究动机

  1. 树结构 LLM 推理的普及：Few-shot learning、Tree of Thoughts、文档 QA 等应用导致查询间共享共同 token 前缀，形成树结构 KV cache
  2. 现有系统的计算模式问题：
  3. 虽然 radix tree 优化了内存布局（SGLang），但 attention 计算仍逐查询独立执行
  4. 共享 KV cache 从慢速 HBM 重复加载（shared memory 复用不足）
  5. 解码阶段 Q 矩阵退化为向量（GEMV），难以利用 tensor core（GEMM 更高效）
  6. FlashAttention 在填充后仅 <1% 有效计算
  7. 核心 gap：树结构内存布局 vs 查询分离的计算模式之间的不匹配

方法

1. 系统架构

FastTree 作为 SGLang 的插件，包含两个核心组件： - Tree Structure-Adaptive Runtime（运行时分组优化） - Efficient Tree-Structured Attention Kernel（高效 kernel 设计）

2. Context-Queries 分组优化

问题定义：给定 radix tree T，寻找最优的边赋值函数 f: E → {0,1}，将节点分组以最小化 kernel 执行延迟。

关键洞察：不同的分组方案对计算模式和内存共享的影响差异巨大。例如： - 将共享前缀 A1+B1 的查询一起处理，可将 GEMV 转为 GEMM，利用 tensor core - 但过度分割可能引入更多中间结果和 reduction 开销

贪心启发式（Algorithm 1）： - BFS 遍历树，对每条边决定是否将父子节点"拼接" - 比较两种赋值的估计开销：SplitKVCost（分割 KV）vs SplitQCost（分割 Q） - 开销模型考虑两个因素： 1. Padding 开销：tile size 不能整除维度时的填充浪费（shared memory + 冗余计算） 2. 中间结果开销：分割产生的额外 reduction 中间结果

3. GPU-Efficient 长上下文分割

解决两个 GPU 利用不足问题： - Block 并行度不足：总 block 数小于 GPU 容量，导致 SM 空闲 - Tail effect：部分节点上下文过长，某些 block 执行时间远超其他

解决方案：运行时将长上下文节点拆分，虽然引入中间结果开销，但可显著提升 GPU 利用率。

4. 树结构 Attention Kernel 设计

One-kernel-accommodating-all： - 用单个 GPU kernel 处理所有分组，每个分组分配独立 block set - 消除 kernel launch 开销

FlashAttention 风格的分组处理： - QKV 矩阵按 tile 分块，Q 维度并行到不同 block，K/V 维度顺序迭代 - 使用 online softmax 将 partial softmax 结果存储在 shared memory - 关键优势： - 共享 KV cache 只加载一次（减少 HBM 交易） - 聚合查询将 GEMV 转为 GEMM（利用 tensor core）

Multi-phase tiling： - 树近根节点（query 多）→ 大 tile size（最大化 KV 复用） - 树近叶节点（query 少）→ 小 tile size（避免 shared memory 浪费，提高 SM 占用率）

优势

  1. 显著加速：对现有 attention kernel 5–10× 加速，端到端 2.2×
  2. 即插即用：作为 SGLang 插件，与现有系统兼容
  3. 运行时自适应：贪心启发式在线生成最优分组，无需离线搜索
  4. 充分利用硬件：GEMV→GEMM 转换，利用 tensor core 和 shared memory
  5. 长上下文优化：分割策略解决 GPU 利用不足

局限性

  1. 仅优化 Decoding：未优化 prefill 阶段（虽然 prefill 问题较小）
  2. CUDAGraph 兼容性：动态分组与 CUDAGraph 的静态图要求冲突，需额外适配
  3. Triton 实现：未利用 Hopper 特有特性（如 TMA），有进一步优化空间
  4. 贪心启发式的局限：在简单树结构中与直接聚合差异不大，但在复杂树中优势显著
  5. 仅针对树结构场景：对非树结构（如纯线性 prefix）无明显优势
