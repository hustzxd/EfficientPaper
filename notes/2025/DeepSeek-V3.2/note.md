## Abstract

We introduce DeepSeek-V3.2, a model that harmonizes high computational efficiency with superior reasoning and agent performance. The key technical breakthroughs of DeepSeek-V3.2 are as follows: (1) DeepSeek Sparse Attention (DSA): We introduce DSA, an efficient attention mechanism that substantially reduces computational complexity while preserving model performance in long-context scenarios. (2) Scalable Reinforcement Learning Framework: By implementing a robust reinforcement learning protocol and scaling post-training compute, DeepSeek-V3.2 performs comparably to GPT-5. Notably, our high-compute variant, DeepSeek-V3.2-Speciale, surpasses GPT-5 and exhibits reasoning proficiency on par with Gemini-3.0-Pro, achieving gold-medal performance in both the 2025 International Mathematical Olympiad (IMO) and the International Olympiad in Informatics (IOI). (3) Large-Scale Agentic Task Synthesis Pipeline: To integrate reasoning into tool-use scenarios, we developed a novel synthesis pipeline that systematically generates training data at scale. This methodology facilitates scalable agentic post-training, yielding substantial improvements in generalization and instruction-following robustness within complex, interactive environments.

## 一句话总结

DeepSeek-V3.2 沿用 V3.2-Exp 的 DSA 架构，将后训练重点推进到稳定扩展 GRPO、工具调用中的推理上下文保留和大规模可验证 Agent 任务合成，在推理、编码及通用工具使用之间做性能与输出成本的折中。

## 创新点

1. **稀疏架构与训练分工清楚。**Lightning Indexer 先对历史 token 打分，再选 top-2,048 个 latent KV 做 MLA 注意力；1,000 步、约 2.1B tokens 的 dense warm-up 只训练 indexer，之后约 943.7B tokens 的 sparse training 更新主模型与 indexer。Indexer 的输入 detach，其训练信号来自与注意力分布对齐的 KL loss，主模型仅用语言建模 loss。该架构与 V3.2-Exp 相同，正式版不是另一套新的 attention。
2. **稳定扩展 GRPO 的四项配方。**对 K3 KL 估计施加当前/采样策略的重要性修正；屏蔽高策略偏移且 advantage 为负的整条序列；Keep Routing 复用 rollout 的 MoE 路由；Keep Sampling Mask 复用 top-p/top-k 的截断支持集，减小训练与推理不一致。正式版将推理、Agent 和对齐任务混合 RL，报告后训练计算预算已超过预训练成本的 10%。Keep Routing 自 V3-0324 已使用，并非本报告首次引入。
3. **让思考在工具调用之间延续。**仅追加工具调用/结果时保留历史 reasoning；收到新用户消息才清除历史 reasoning，同时保留工具调用与结果，避免每次工具返回都重做推理。使用 `user` 消息模拟工具输出的框架可能提前触发清理，论文建议此类框架采用 non-thinking 模式；因此角色与模板是执行语义的一部分。
4. **以环境、工具、任务和 verifier 共同合成训练数据。**四类任务共 85,267 个：code agent 24,667、search 50,275、general agent 4,417、code interpreter 5,908。代码任务从 GitHub issue/PR 构建可执行环境；通用任务逐步增加约束、联合生成工具与验证函数，保留 pass@100 非零的实例，最终有 1,827 个合成环境。搜索任务用多模型候选和搜索验证筛选难题，再结合 rubric reward。这里“8.5 万任务”包含真实环境中的抽取/合成 prompt，不能全称为合成环境。

## 带来什么提升

1. **正式版的推理与 Agent 结果（表 2）：**Thinking 模式 AIME 2025 为 93.1、HMMT Feb 为 92.5、LiveCodeBench 为 83.3；SWE-bench Verified 为 73.1%、SWE Multilingual 为 70.2%、Terminal Bench 2.0 为 46.4%、MCP-Mark 为 38.0%、Tool-Decathlon 为 35.2%。这些是模型与对应 harness 的组合成绩，不能统一解释为模型权重的独立提升。
2. **Speciale 用更多输出计算换更强推理（表 3、4）：**AIME 2025 为 96.0、HMMT Feb 为 99.2、IMOAnswerBench 为 84.5；IMO 35/42、IOI 492/600、ICPC WF 解出 10/12 题。相应输出预算也更大，例如 Codeforces 平均输出约 77K tokens，普通 Thinking 约 42K、Gemini-3.0-Pro 约 22K。Speciale 仅训练推理数据并减轻长度惩罚，官方模型卡注明不支持工具调用，不能当作普通 V3.2 Agent 的增强版。
3. **工具推理与合成 RL 有单独证据。**同为 Claude Code harness，Thinking 相对 non-thinking 的 Terminal Bench 2.0 从 37.1 到 46.4，MCP-Mark 从 26.5 到 38.0（附录 C）。另在 non-thinking 的 SFT checkpoint 上只训练合成通用 Agent 数据，图 5 显示 Tau2Bench/MCP-Mark/MCP-Universe 改善，用于支持训练任务向新环境迁移；不将主模型的全部收益归因于这一消融。
4. **上下文管理扩大 test-time compute。**BrowseComp 表 2 不做上下文管理为 51.4，加入后为 67.6。上下文占用超过 80% 时，论文比较 Summary、Discard-75%、Discard-all 与并行采样；Discard-all 在该实验中表现较好。它扩大了可执行步数，不能把 67.6 当作同预算、无上下文处理的单次 rollout 成绩，也不能据此外推丢弃历史对所有 Agent 都安全。

## 备注

- **复杂度与缓存边界：**DSA 主模型核心注意力从 $O(L^2)$ 变为 $O(Lk)$，但 indexer 仍为 $O(L^2)$；top-k 稀疏访问也不等于完整历史 KV 可以只保留 k 个。图 3 是 H800 服务基准按每 GPU-hour 2 美元估算的 token 成本，不是任意硬件、并发或缓存状态下的普遍时延结论。
- **评测依赖 harness 与预算：**Terminal Bench 的 46.4 使用 Claude Code；Terminus non-thinking 为 39.3。SWE Verified 73.1 使用内部框架，其他设置约 72–74；MCP 评测也使用内部环境。IMO/CMO 采用 generate-verify-refine；IOI 每题先采样 500 个候选，再按样例测试等过滤并选 50 个提交，ICPC 每题先生成 32 个。因此“金牌水平”是这些评测流程下的结果，不是一次生成的 pass@1。论文还指出多余自验证会使轨迹超过 128K，知识广度、token 效率和复杂任务仍有不足。
