SliceGPT: Compress Large Language Models by Deleting Rows and Columns

一句话总结

SliceGPT 是一种基于计算不变性（Computational Invariance）的后训练结构化剪枝方法，通过对 Transformer 权重矩阵施加正交变换（PCA）后直接删除行和列，从而压缩模型的嵌入维度，实现了在不进行恢复微调的情况下移除高达 25% 参数并保持接近原始模型性能的零样本表现，同时带来显著的推理加速。

摘要翻译

大语言模型已成为自然语言处理的基石，但其使用伴随着巨大的计算和内存资源开销。稀疏化为缓解这些资源限制提供了方案，近期研究表明训练好的模型可以在后训练阶段被稀疏化。现有稀疏化技术面临挑战，因为它们需要额外的数据结构，且在当前硬件上提供的加速受限。本文提出了 SliceGPT，一种新的后训练稀疏化方案，它用更小的（密集）矩阵替换每个权重矩阵，从而减少网络的嵌入维度。通过大量实验，我们表明 SliceGPT 可以为 LLAMA-2 70B、OPT 66B 和 Phi-2 模型移除高达 25% 的参数（包括嵌入层），同时分别保持密集模型 99%、99% 和 90% 的零样本任务性能。我们的切片模型在更少的 GPU 上运行且速度更快，无需任何额外的代码优化：在 24GB 消费级 GPU 上，我们将 LLAMA-2 70B 推理的总计算量减少到密集模型的 64%；在 40GB A100 GPU 上减少到 66%。我们提出了一个新的洞察——Transformer 网络中的计算不变性，它使 SliceGPT 得以实现，我们希望它能启发并开启未来减少预训练模型内存和计算需求的新途径。代码地址：https://github.com/microsoft/TransformerCompression

研究动机

大语言模型（LLMs）的参数规模达到数十亿甚至上千亿，部署成本极高。许多模型需要多块 GPU 才能进行预测，且由于自回归特性，生成文本需要多次前向传播。因此，降低模型的计算需求具有广泛的研究兴趣。

现有的模型压缩技术主要分为四类：蒸馏、张量分解（包括低秩因子化）、剪枝和量化。其中，剪枝方法虽然历史悠久，但大多数方法需要在剪枝后进行恢复微调（RFT）才能维持性能，使整个过程昂贵且难以扩展。此外，现有的非结构化和半结构化剪枝方法面临以下问题：

  1. 非结构化稀疏（如 SparseGPT）虽然能够达到较高的稀疏率，但在当前硬件上无法实现端到端的加速，因为稀疏模式需要额外的数据结构支持。
  2. 2:4 结构化稀疏虽然能够利用硬件加速，但模型精度维持不如预期。
  3. 低秩分解方法需要将内维度压缩到原始维度的一半以下，且通常需要微调步骤。
  4. 基于范数的列/行剪枝效果极差，WikiText-2 困惑度在剪枝少量列后就飙升到 1000 以上。

SliceGPT 的核心动机是：是否存在一种方法，能够将权重矩阵直接替换为更小的密集矩阵，减少网络的嵌入维度，同时不需要恢复微调？ 答案是肯定的，通过利用 Transformer 架构中固有的计算不变性来实现。

实验结果

数据集和模型

  • 模型：OPT（125M 到 66B）、LLAMA-2（7B 到 70B）、Phi-2（2.8B）
  • 校准集：WikiText-2 训练集和 Alpaca 训练集
  • 评估任务：WikiText-2 生成任务（困惑度）、五个零样本任务（PIQA、WinoGrande、HellaSwag、ARC-e、ARC-c）
  • 硬件：Quadro RTX6000（24GB 消费级）、A100（40GB 数据中心级）、H100（80GB 数据中心级）
  • 计算成本：单张 H100 GPU，约 3.5 小时完成 LLAMA-2 70B 的计算

WikiText-2 困惑度结果

SliceGPT 在 OPT 模型上的表现优于 LLAMA-2，且性能随模型规模增大而提升。具体数据（25% 切片）：

模型 Dense SliceGPT 25% SparseGPT 2:4
OPT 66B 9.33 9.68 10.22
LLAMA-2 70B 3.32 4.60 4.98
OPT 30B 9.56 10.04 10.53

SliceGPT 在所有 LLAMA-2 模型上优于 SparseGPT 2:4，在 OPT 模型上（除 2.7B 外）也优于 SparseGPT 2:4。

零样本任务表现

  • OPT 66B：25% 切片后保持 99% 密集模型性能
  • LLAMA-2 70B：25% 切片后保持 96% 性能，加上 RFT 后提升到 99%
  • Phi-2：25% 切片后保持 87% 性能，加上 RFT 后提升到 90%

使用 Alpaca 作为校准和 RFT 数据集时，LLAMA-2 70B 在 30% 切片后平均准确率达 74.3%（密集模型 76.6%），切片后模型约 51.6B 参数。

吞吐量和推理加速

吞吐量（H100 GPU）： - 25% 切片：最高 1.55× 吞吐量提升 - 50% 切片：最大模型只需 1 块 GPU 而非 2 块，3.13× 和 1.87× 吞吐量提升 - 固定 GPU 数量下，50% 切片可达 6.26× 和 3.75× 密集模型吞吐量

推理时间： - 在 Quadro RTX6000 上，25% 切片带来 16-17% 加速 - 在 A100 上，25% 切片带来 11-13% 加速 - LLAMA-2 70B 在 RTX6000 上，计算量从 1764 GPUms 减少到 1075 GPUms（64%） - LLAMA-2 70B 在 A100 上，计算量从 500 GPUms 减少到 330 GPUms（66%）

计算成本

所有 LLAMA-2、OPT 和 Phi-2 模型可在单块 GPU 上 1-3 小时内完成切片。加上恢复微调（RFT），总时间 1-5 小时： - LLAMA-2 7B：1 小时 7 分钟（1xH100） - LLAMA-2 13B：1 小时 52 分钟（1xH100） - LLAMA-2 70B：5 小时 6 分钟（1xH100 切片 + 4xH100 RFT） - Phi-2：2 小时 48 分钟（1xV100）

校准集敏感性

  • 校准集大小至少 128 个样本即可获得合理结果
  • 更大的序列长度（如 2048）能带来更好的困惑度
  • 主实验使用校准集大小 1024，序列长度 2048

优势

  1. 无需恢复微调：SliceGPT 在不进行 RFT 的情况下仍能保持较好的性能，而大多数结构化剪枝方法（如 LLM-Pruner）需要昂贵的微调步骤。

  2. 真正的结构化压缩：不同于非结构化稀疏或 2:4 结构化稀疏，SliceGPT 直接删除权重矩阵的行和列，减少了嵌入维度，使得模型能使用密集矩阵内核，无需额外的稀疏数据结构支持。

  3. 显著的加速效果：由于减小了嵌入维度，SliceGPT 在减少参数的同时也减少了计算量和数据移动，带来真实的端到端加速（在消费者级 GPU 上可达 16-17% 加速）。

  4. 计算成本低：仅需单块 GPU 和数小时即可完成，远低于需要多次迭代训练的压缩方法。

  5. 利用计算不变性：理论基础扎实，通过正交变换和 RMSNorm 的可交换性，保证了变换后模型输出不变，提供了简洁的理论框架。

  6. 模型越大效果越好：更大的模型（如 LLAMA-2 70B）能够承受更高的压缩率，且保持较好的性能，说明该方法对大模型特别有效。

  7. 可与量化等方法结合：SliceGPT 的结构化压缩可以与量化（如 GPTQ、SmoothQuant）结合，进一步压缩模型。

局限

  1. 需要额外的残差连接操作：每个块需要插入 的线性变换，虽然开销较小但无法预计算，增加了少量 的计算。

  2. 需要校准数据集：计算 PCA 变换矩阵需要从训练集中选择校准数据集，且校准集的大小和序列长度对性能有影响，增加了额外的数据依赖。

  3. 大模型上 FP32 PCA 更准确：使用 FP32 进行 PCA 计算需要更高的精度，这在大模型上可能影响数值稳定性（论文发现单精度会导致精度下降）。

  4. 对小模型效果有限：虽然 Phi-2（2.8B）等小模型也能被压缩，但切片后模型与相同参数量的小模型相比仍有差距，说明压缩后的效果不如同等规模的原生模型。

  5. 无法进行完全的端到端加速优化：虽然提供了加速，但在某些情况下（如通过 Hugging Face 推理）无法享受连续批处理和模型分片的优化。

  6. 恢复微调效果依赖于校准集：使用 WikiText-2 进行 RFT 效果远不如 Alpaca，说明 RFT 效果高度依赖于校准数据集与目标任务的相似性。

  7. 50% 切片时困惑度较高：当切片率超过 25% 时（如 50%），WikiText-2 的困惑度比 SparseGPT 2:4 更差，尽管吞吐量更高。

  8. OPT 模型的 RFT 效果有限：论文尝试了大量搜索，未能找到使 OPT 模型在 RFT 后性能提升的参数。

与 EfficientPaper 相关的研究方向

  1. 结构化剪枝（Structured Pruning）：SliceGPT 属于结构化剪枝范畴，与 LLM-Pruner、LLM Surgeon 等方法相关。EfficientPaper 项目关注高效模型压缩技术，SliceGPT 的结构化剪枝方法是其中的重要方向。

  2. 计算不变性（Computational Invariance）：这是一个新的理论洞察，可能启发更多关于 Transformer 架构中正交变换的研究，如在不同层之间应用正交变换以优化模型结构。

  3. 后训练压缩（Post-training Compression）：SliceGPT 的后训练剪枝方式与 GPTQ（量化）、SparseGPT（非结构化剪枝）等方法形成互补，为后训练压缩提供了新的思路。

  4. 模型稀疏化（Model Sparsification）：通过删除行和列实现的结构化稀疏化，与非结构化稀疏（如 SparseGPT 的 2:4 模式）和低秩分解方法形成对比，提供了不同稀疏化策略的研究方向。

  5. 模型部署优化（Model Deployment Optimization）：SliceGPT 在减少 GPU 需求和推理时间方面的效果，对于模型部署和推理优化有重要价值，特别是对于资源受限的消费级 GPU 环境。

  6. 与量化的结合（Compression Combination）：SliceGPT 可以与量化方法（如 GPTQ、SmoothQuant、LLM.int8()）结合，实现更高效的模型压缩，这是当前研究的热门方向。

  7. 大模型压缩（Large Model Compression）：SliceGPT 对大模型（如 LLAMA-2 70B）的高效压缩，与 EfficientPaper 项目中关注的大模型效率研究方向高度一致。

  8. 校准数据集研究（Calibration Dataset Study）：SliceGPT 对校准数据集大小和序列长度的敏感性研究，为后续工作提供了重要参考，可能启发更多关于校准数据选择和优化的研究。
